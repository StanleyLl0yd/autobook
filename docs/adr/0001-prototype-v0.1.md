# ADR-0001: Prototype v0.1 architecture

- Status: Accepted
- Date: 2026-08-26

## Context

AutoBook must already be useful for recording the real service history of one vehicle, work offline, remain understandable to a non-enthusiast, and avoid backend or account work before it creates user value.

## Decision

### Client and state

- Flutter and Dart provide one Android-first codebase.
- Riverpod is the only state-management system.
- `go_router` owns navigation.
- UI, domain calculations, and data access are separated without one-use abstractions.

### Persistence

- Drift opens an on-device SQLite database.
- UUID text keys are used for sync-ready identity.
- Costs remain on their source service events. Expense summaries are queries, not duplicated rows.
- Mileage changes are immutable history records; `vehicles.current_mileage` is the current projection.
- Maintenance schedules store their last known event and interval. Deleting an event will later recalculate them from the preceding matching item.

### Minimum data model

| Entity | Prototype fields |
| --- | --- |
| Vehicle | id, brand, model, year, current mileage, nickname, created/updated timestamps |
| Mileage record | id, vehicle id, mileage, recorded timestamp |
| Service event | id, vehicle id, category, date, mileage, service location, total cost, currency, comment, timestamps |
| Service item | id, event id, maintenance type, title, comment |
| Maintenance schedule | id, vehicle id, maintenance type, interval km/months, last date/mileage, next date/mileage, enabled |

Parts, files, guarantees, tyres, independent expenses, accounts, and sync metadata remain outside v0.1.

### Navigation flow

```text
App entry
├── no vehicle → Add vehicle → Dashboard
└── vehicle exists → Dashboard

Dashboard ↔ History ↔ Expenses ↔ Vehicle
     ├── Update mileage
     └── Add service
```

The bottom action opens Add Service directly because routine maintenance is the highest-frequency core action.

### Maintenance calculation

- `next_mileage = last_mileage + interval_km` when a kilometre interval exists.
- `next_date = last_date + interval_months` when a time interval exists.
- Both thresholds stay visible; whichever becomes due first in real usage determines urgency.
- Remaining distance is recalculated from the vehicle's current mileage, not stored as truth.

## Consequences

- The prototype is fully usable offline and has no account friction.
- Query code is explicit and testable, but the first database layer uses Drift custom SQL instead of generated table classes. Generated Drift tables can be introduced when the schema expands.
- Android runner files must be generated by a local Flutter SDK; the source project does not pin a machine-specific SDK path or signing credentials.
