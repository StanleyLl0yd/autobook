# ADR-0002: v0.1.1 hardening and release integrity

- Status: Accepted
- Date: 2026-08-28

## Context

The initial prototype proved the core vehicle-history flow, but it still used
template Android branding, inherited backup behavior, and a single release job
with broader permissions than each individual step required. The database also
had no executable guard against an unplanned schema-version change.

## Decision

### Local data

- Android cloud backup and device-to-device transfer are disabled.
- Schema version changes require explicit Drift migrations.
- An unknown upgrade path fails before modifying or recreating user data.
- Tests cover the current schema, foreign keys, cascade deletion, and the
  fail-closed migration path.

User-controlled export and encrypted backup remain future features. Disabling
implicit platform backup avoids creating a second, invisible data policy first.

### Build and supply chain

- CI builds debug APK, R8-minified release APK, and release AAB outputs.
- CI release artifacts use an ephemeral key and cannot be mistaken for official
  releases.
- Gradle verifies its distribution against the official SHA-256 checksum.
- Third-party GitHub Actions are pinned to full commit SHAs.
- Dependabot monitors Dart, Gradle, and GitHub Actions dependencies.

### Release publication

- Validation, signing, and publication use separate jobs and least-privilege
  permissions.
- The protected release environment is available only to the signing job.
- APK Signature Schemes v2 and v3, one APK signer, and the expected APK/AAB
  certificate fingerprint are required.
- Every APK and AAB is accompanied by a SHA-256 checksum.
- Existing tags and GitHub Releases are never overwritten.

### Presentation and ownership

- AutoBook uses a dedicated launcher, adaptive icon, monochrome icon, and splash
  mark instead of Flutter template assets.
- The About screen exposes the exact app version, author, privacy boundary,
  source repository, and license.
- Source code is available under PolyForm Noncommercial 1.0.0.

## Consequences

- Local history cannot silently follow the user through Android backup or
  device migration.
- A future database change must ship with a tested migration before the app can
  open the newer schema.
- Official releases are distinguishable from CI artifacts and are reproducibly
  tied to a main-branch commit and one signing certificate.
- Commercial reuse is not granted by the public source license.
